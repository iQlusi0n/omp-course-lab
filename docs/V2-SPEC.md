# omp-course-lab v2 — capstone feature set

Ship all four items below as a reviewed, committed, documented change. Start
from tag `module-15-start`. Everything in `docs/spec.md` stays true unless this
document says otherwise.

## 1. Migration: `users.company` and schema version 2

- Add `tools/migrate.py`: idempotent, run as `python3 tools/migrate.py [--db PATH]`.
  It adds a nullable `company TEXT` column to `users` and sets
  `schema_version.version = 2`. Running it twice is a no-op that prints
  `already at version 2`.
- Regenerate `generated/schema_info.py` **through the tool** (`SCHEMA_VERSION = 2`).
  Never hand-edit `generated/`.
- `tools/seed_db.py` creates version-2 databases from now on (fresh seeds must
  not need the migration).
- Commit the migrated `data/lab.sqlite`.

## 2. New endpoint: `GET /users/<id>/orders`

- Returns `{"user_id": <id>, "count": <n>, "orders": [...]}` with the user's
  orders newest first (same order shape as `/orders`), **no pagination**.
- Optional `?status=<status>` filter; an unknown status → `400` naming the valid
  values (`generated.schema_info.STATUSES`).
- `404` when the user does not exist.
- `GET /users/<id>` gains `"company"` (null when unset).

## 3. CLI flag: `orders --status`

- `python3 -m cli orders [--month YYYY-MM] [--status STATUS]` filters by status
  in addition to month; both filters combine with AND.
- Invalid status → argparse `choices` error (exit 2).
- Works with `--format csv` if issue #3 has been done; otherwise table only.

## 4. Web form: optional `company` field

- `web/index.html` gets `<input id="company" name="company">` (optional) between
  email and the button; `web/app.js` sends it in the JSON body.
- `POST /signup` stores `company` when present and echoes it in the `201` body.
- The success banner text is unchanged: `Welcome aboard!`.
